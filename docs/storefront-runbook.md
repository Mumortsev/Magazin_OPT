# Запуск оптового магазина

Витрина и админка используют FastAPI и один origin. Действующий Telegram Mini App имеет собственную точку запуска. Материалы аудита и соответствие функций описаны в [аудите](storefront-audit.md).

## Локальный запуск

Из корня репозитория соберите сайт.

```sh
cd storefront
pnpm install --frozen-lockfile
pnpm build
cd ../backend
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
mkdir -p data
export DATABASE_URL=sqlite+aiosqlite:///./data/wholesale-local.db
export SHOP_ORIGIN=http://127.0.0.1:8019
export SHOP_MEDIA_DIR=./data/uploads
python -m api.web.manage migrate
python -m api.web.manage add-staff admin 'Администратор' admin
python -m api.web.manage add-staff manager 'Менеджер' manager
uvicorn api.web.app:app --host 127.0.0.1 --port 8019
```

Каталог и заявки находятся в SQLite. Начальный каталог пуст в новой базе. Создайте категорию и товар в `/admin` или загрузите таблицу через «Импорт». Первый пароль запрашивается в терминале. Передайте `--email` при создании учётной записи для получения почты. `disable-staff LOGIN` отзывает сеансы и прекращает доставку на устройства сотрудника. Запускайте `python -m api.web.manage cleanup` периодически для удаления истёкших сессий и предпросмотров.

## Данные и миграция

1. Сделайте согласованную копию базы штатной командой SQLite `.backup` или через `sqlite3.Connection.backup`. Отдельно скопируйте каталог изображений. Храните копии с ограниченным доступом и проверьте восстановление.
2. Укажите путь к копии через `DATABASE_URL` и общий каталог изображения через `SHOP_MEDIA_DIR`. Запустите `python -m api.web.manage migrate`. Команда создаёт добавочные таблицы. Если базовые таблицы имеют несовместимую схему, она останавливается и перечисляет недостающие поля. Сверьте число товаров, категорий, заказов, позиций и распределение старых статусов.
3. Для отдельного сервиса укажите `SHOP_DIST_DIR`, если сборка лежит за пределами `storefront/dist`. На HTTPS задайте `SHOP_ORIGIN` с точным публичным origin. Прокси должен направлять `/`, `/admin` и `/api/v1` на FastAPI, сохранить cookie и заголовки Origin, пропускать SSE без буферизации и ограничить доверие к proxy headers. Для SQLite нужен общий локальный постоянный диск. При раздельных хостах используйте собственную копию БД для запуска до переноса на общий сервер.
4. Остановка нового приложения сохраняет исходные и добавленные таблицы. Для отката после начала приёма заявок сначала сохраните актуальную базу и сверяйте заявки, поступившие после миграции, с резервной копией.
5. GitHub Pages собирал статическую демоверсию при изменении main. Боевой сайт требует FastAPI и постоянного хранилища. Публикация нового сайта и изменение main требуют отдельного решения.

## Работа с Telegram Mini App

Для совместной работы на одной базе запустите старое приложение `api.main:app` на отдельном origin и задайте ему и боту `SHOP_SHARED_LEGACY=true`, `SHOP_LEGACY_BOT_KEY` со случайным секретом от 32 символов, существующий `BOT_TOKEN` и точный `WEBAPP_URL`. В обоих сервисах укажите одну и ту же БД и каталог изображений. Укажите `SHOP_ADMIN_URL` с HTTPS-адресом нового `/admin` для перехода из старого меню. Telegram initData проверяется на сервере, а административные вызовы бота используют серверный ключ. Старый запуск с выключенным режимом совместимости нельзя подключать к общей базе нового сайта.

В совместном режиме история профиля ограничена заказами проверенной Telegram или WhatsApp учётной записи. Старые заявки, объединявшиеся по телефону, введённому при заказе без проверки номера, остаются доступными менеджерам в админке. Старые FCM-клиенты, прежний вход по ID и desktop-обёртки не входят в новый веб-сайт.

Если используется WhatsApp, в совместном режиме установите секреты `WHATSAPP_VERIFY_TOKEN` и `SHOP_WHATSAPP_WEBHOOK_KEY` длиной от 32 символов. Зарегистрируйте у провайдера webhook с параметром `hook_key` и защитите этот параметр в журналах прокси. Старые ссылки на профиль, подписанные другим ключом, обновляются через бота. Ссылка на PDF действует до часа. Настройки реального бота и провайдера проверяются отдельно при подготовке переноса.

## Доставка уведомлений

- Задайте существующую пару `VAPID_PUBLIC_KEY` и `VAPID_PRIVATE_KEY`, а также `VAPID_CLAIM_EMAIL=mailto:...`. Менеджер открывает «Уведомления» и разрешает Web Push для конкретного браузера. Обработчик ограничен разделом `/admin/`, манифест и offline-режим отсутствуют.
- Для резервной почты задайте `SHOP_SMTP_HOST`, `SHOP_SMTP_FROM`, `SHOP_SMTP_MODE` (`starttls` или `ssl`), при необходимости `SHOP_SMTP_PORT`, `SHOP_SMTP_USER`, `SHOP_SMTP_PASSWORD`. Почта получает ссылку в админку, номер и сумму заявки.
- Задание создаётся одновременно с заявкой. Сбой процесса оставляет запись на повторную попытку по истечении аренды. После шести неудач администратор может повторить отправку из журнала. Как и для других очередей с повторной доставкой, после сбоя между подтверждением транспорта и записью результата возможен дубль сообщения. Некорректные подписки с HTTP 404 или 410 отключаются.
- Доступ к заявке из Web Push определяется текущей серверной сессией. Пароль, контакты покупателя и состав корзины в push отсутствуют.

## Проверки перед сдачей

- Сборка TypeScript и Vite, компиляция Python, проверка синтаксиса worker и скрипта запуска.
- Повторный прогон миграции на отдельной БД с историческими статусами и категорией.
- HTTP-сценарии на временной базе. Поиск кириллицей и по артикулу, категории, остатки, CMS и SEO, права сотрудника, CSRF, повторная заявка, серверная сумма, параллельный захват, история, SSE, импорт CSV, загрузка WebP и отказ невалидного изображения.
- Совместный запуск двух сервисов на одной тестовой базе. Покупательские маршруты Mini App, проверка подписанных Telegram-данных, статус из бота и история в веб-админке.
- Локальный SMTP с TLS, ошибка отправки и журнал, восстановление задания с истёкшей арендой, отключение подписки на симулированном ответе Web Push HTTP 410.
- Cloud Chrome не запустился из-за ошибки среды. Мобильные и клавиатурные сценарии в браузере, подписка и доставка через реальный Web Push, реальные учётные данные Telegram и WhatsApp, размещение сайта и перенос боевой БД требуют проверки на тестовом контуре.

## Публикация витрины на GitHub Pages

Публичный адрес — https://mumortsev.github.io/Magazin_OPT/. GitHub Pages отдаёт сборку Vite, а каталог, оформление и база работают на отдельном HTTPS-сервере FastAPI. Ссылка «Для сотрудников» открывает админку на сервере FastAPI. Её сессии, SSE и Web Push используют его origin.

1. Соберите и запустите сервер по инструкции выше. Установите `SHOP_ORIGIN` равным его HTTPS-origin и `SHOP_PAGES_ORIGIN=https://mumortsev.github.io`. Передайте серверу обычную сборку `pnpm build` с путями от корня.
2. Задайте переменную репозитория GitHub Actions `SHOP_API_ORIGIN` с HTTPS-origin FastAPI. Workflow проверит ответ каталога и разрешение CORS на отправку заявки до замены текущей публикации.
3. Запустите workflow `Publish wholesale storefront to Pages` после согласования публикации. Он соберёт витрину с путями `/Magazin_OPT/` и адресом API. Отдельную локальную сборку Pages можно проверить командой `VITE_SHOP_API_ORIGIN=https://api.example.org pnpm build --mode github-pages`.

На момент проверки прежний адрес Amvera возвращал HTTP 503. Текущая публикация Pages по-прежнему показывает исходную демоверсию.

### Ссылка на админку и тестовый вход

После публикации сотрудник может открыть https://mumortsev.github.io/Magazin_OPT/admin/. Страница Pages переводит браузер на `/admin` HTTPS-сервера FastAPI, где выполняется вход. Там хранятся сессии и доступны заявки.

Для проверки на **отдельной локальной базе** после команды `migrate` выполните `export SHOP_LOCAL_ADMIN=true` и `python -m api.web.manage add-local-admin`. Команда создаёт администратора `admin` с паролем `admin` и сохраняет хеш Argon2. Существующая запись с таким логином сохраняется. С той же переменной запустите FastAPI на `127.0.0.1` и откройте http://127.0.0.1:8019/admin/. Для публичного сервера используйте `python -m api.web.manage add-staff admin 'Администратор' admin` и задайте пароль через терминал. Пара `admin` / `admin` отключена на HTTPS и при запросах извне локальной машины.

### Бесплатная демонстрация для показа

При обычной публикации GitHub Pages собирает `pnpm build --mode github-pages-demo`. Витрина и панель сотрудников открываются на Pages без FastAPI. Доступ к демо-админке — `admin` / `admin`. Каталог, содержимое и тестовые заявки записываются в браузере. При оформлении автоматически подставляется тестовый покупатель. Для боевого размещения запустите workflow вручную с параметром `live` и настройте HTTPS API.
